# LM Chat 管理员手册

> 面向服务器管理员。服务端是"哑管道"：只转发加密数据，无法读取任何消息内容。

## 1. 日常管理命令（admin 三连 + cleanup）

admin 功能内置在 imserver 二进制里，**用 imsvc 用户跑**（避免弄乱数据文件属主）：

```bash
# 列出所有账号（ID / 昵称 / 最后活跃）
sudo -u imsvc /opt/imserver/imserver -admin list

# 删除指定账号（封人/清号）
# 会连带清理该账号的 prekeys / envelopes / blobs / 名下的群
sudo -u imsvc /opt/imserver/imserver -admin del <32位账号ID>

# 换邀请码（泄露/用滥时轮换；改的是 config.json 里的 invite）
sudo -u imsvc /opt/imserver/imserver -admin invite <新邀请码>

# 手动触发过期清理（消息/blob 超过 TTL 的）
sudo -u imsvc /opt/imserver/imserver -admin cleanup

# 检查"群主已注销"的孤儿群（默认只列出，加 --del 才删除）
sudo -u imsvc /opt/imserver/imserver -admin orphan-groups
sudo -u imsvc /opt/imserver/imserver -admin orphan-groups --del
```

> ⚠️ **`-config` 要放在子命令前面**：`imserver -admin -config /path/config.json <子命令>`。
> 省略 `-config` 时用的是默认路径 `/opt/imserver/config.json`。**别在"没生效"时去掉
> `-config` 重试** —— 那反而会操作到默认的生产库。

注意：`invite` 会改配置，改完按常规流程 `systemctl restart imserver` 生效（这是计划内重启，挑没人用的时间做）。

## 2. 备份与恢复

- 脚本：`/usr/local/sbin/im-backup.sh`（在线快照，不影响运行中服务）
- 定时：每天 **04:17**（`/etc/cron.d/im-backup`），日志追加到 `/var/log/im-backup.log`
- 产物：`/opt/backups/im-backup-YYYYmmdd-HHMM.tar.gz`（含数据库 + config），**自动保留最近 7 份**

手动备份：直接跑 `sudo /usr/local/sbin/im-backup.sh`

**恢复步骤：**

```bash
# 1. 解包
tar -xzf /opt/backups/im-backup-XXXX.tar.gz -C /tmp/
# 2. 停服务
systemctl stop imserver
# 3. 覆盖数据库（注意保留 imsvc 属主，WAL/SHM 一起清掉）
rm -f /opt/imserver/data/im.db-wal /opt/imserver/data/im.db-shm
cp /tmp/im-XXXX.db /opt/imserver/data/im.db
chown imsvc:imsvc /opt/imserver/data/im.db
# 4. 起服务、验证
systemctl start imserver
curl -s http://127.0.0.1:8420/health
```

## 3. 消息配额（防灌库）

`envelopes` 表此前只有 TTL 回收、没有容量上限，单个账号可以无限量发消息。
现在 `hSend` 会按**收件账号**检查两个上限，超出返回 `507 recipient quota exceeded`：

| 配置项 | 默认 | 含义 |
|---|---|---|
| `msg_quota_mb` | 200 | 单账号待投递消息**总字节**上限 |
| `msg_quota_count` | 20000 | 单账号待投递消息**条数**上限 |

改 `config.json` 后需重启服务生效。注意这是 check-then-act，并发下可能略微超额，
但超出的部分仍受 TTL 回收，实际影响可忽略。

排查"某人收不到消息"时，先看是不是撞了配额：

```bash
# 查某账号当前的待投递量
sudo -u imsvc sqlite3 /opt/imserver/data/im.db \
  "SELECT COUNT(*), SUM(LENGTH(payload)) FROM envelopes WHERE dest='<账号ID>';"
```

## 4. 监控

- 脚本：`/usr/local/sbin/im-watch.sh`，每 10 分钟（`/etc/cron.d/im-watch`）
- 检查：服务 active 状态（挂了自动拉起并记录）、根分区 >85%、可用内存 <150MB
- 告警日志：`/var/log/im-watch.log`（weekly 轮转，留 4 份）
- **巡检日志只在出事时写**，平时是空的，不是坏了

## 5. 客户端 APK 发布流程

1. 构建产物：`/opt/android-app/dist/lmchat.apk`（由 `/opt/android-app/build.sh` 产出）
2. 发布前自检：`apksigner verify --print-certs /opt/android-app/dist/lmchat.apk`
3. 发到群文件，群友覆盖安装即可（签名一致可直接升级）
4. versionCode 递增规则：每次对外发布 +1（`app/AndroidManifest.xml`），否则老用户升不了级

## 6. 快速排障

```bash
systemctl status imserver          # 服务状态
tail -n 50 /var/log/im-watch.log   # 有没有历史告警
journalctl -u imserver -n 100      # 服务自身日志（注册/异常都在这）
curl -s http://127.0.0.1:8420/health   # 应返回 {"accounts":N,"ok":true}
tail -n 20 /var/log/nginx/error.log    # 公网入口问题看这
```
